# DEV-084 · 实际输入来源与执行归因

完成日期2026-11-01。继续开发时发现原输入确认只核对动作与回执，缺少明确的自动操作排除边界；按docs/design/input-origin-attribution.md先登记方案，再实现请求关联和保守归因。本任务不实现用户暂缓的重试。

Engine对观察到的游戏输入记录方法与来源分类，服务端回执引用原请求记录，receipt引用实际请求ID与确认ID。新字段只属于执行诊断，不增加可重建的麻将事件字段，不重复保存手牌快照。请求与回执仍被当前游戏连接隔离，实际牌局只由输入适配器观察到的事件更新。

当前真实客户端timeuse=1000000为已知自动操作标记；严格匹配整数，其他数值/缺失/异常类型保持unverified，不据此证明输入来自bot。Coordinator对同窗口自动请求及其接受回执不记录模型server_confirmed，不采纳拟议小局计划；同牌自动弃牌也保持实际弃牌事实并另记归因失败。早于鼠标事务完成的回执沿用延后处理，停止后回包不恢复输入。没有重试、补点、策略代打或模型配置变更。

match-report.v2-input-origin列出客户端自动请求及请求/回执引用。重算旧数据时若窗口存在自动操作，则保留旧确认曾存在的事实并排除当前AI成功计数；不改原receipt或旧冻结报告。实战工具见到当前机会中的自动操作即保留失败并停止。旧缺方法/请求引用保持null或缺省，不补造。

新增tools/audit_input_attribution.py使用SQLite只读一致性事务核对请求/响应/receipt的场、小局和窗口引用，检查有直接证据的自动操作误确认。passed只代表可核对部分无错误，不能掩盖legacy_unlinked_acks及receipts_without_request_refs。核验前真实档案1263次请求、33次已知自动请求、1229个旧无请求引用回执，零归因审计错误；没有发现33个自动请求被直接确认成AI成功，新运行保护由构造反例验证。

最终源码368项pytest通过，ruff及任务检查通过。专项覆盖精确标记、三种动作、同牌事件、正常/自动早回包、重复引用、不同窗口、拒绝、停止、模型等待取消、真实pass振听、只读审计错场和旧报告重算。实际已登录profile通过窄登录命令重新认证；服务在无活动对局时重载并接回专用浏览器，新四人南5＋10一真人三电脑场已观察32次正常确认（弃牌、跳过、立直、荣和、吃），请求关联和牌局重放检查通过。完整实战结果另冻结，不以本任务消费冒充500窗口或三场完成。
