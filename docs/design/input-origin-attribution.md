# DEV-084 · 实际输入来源与执行归因

2026-11-01。继续开发先补实际输入归因，再开展独立5＋10实战。当前DEV-082/VAL-014仍按用户要求暂缓；本任务不新增重试、恢复、补点或本地策略。

已有真实客户端输入中出现timeuse=1000000的自动操作标记。它必须与鼠标发送、RPC接受和牌局事件分别保存：即使自动跳过或自动动作恰好与模型选择相同，也不能据此确认模型成功。普通timeuse仅表示没有这个已知标记，不能自动证明输入来自bot；缺失和其他值保持来源未确定。不改动真实牌谱，不猜客户端未提供的来源。

最小实现：客户端输入记录带方法、来源分类与自身记录ID，服务端确认引用原请求记录，不复制新牌谱字段；单个内存pending关联实际请求ID，receipt引用这些ID及确认ID。自动操作的接受回执或后续实际事件触发明确失败归因，不更新本小局计划，不认作server_confirmed。按下完成前到达的接受回执仍延迟到输入事务完成后处理；手工停止与未知提交沿用现有行为。

match_report加入自动操作与请求/响应引用，已知自动操作不能进入AI成功数；保留旧receipt原文和原失败报告，按新增报告版本给出重算口径。旧档案缺方法/引用不补造，不把未知当自动或成功。报告需要区分已有鼠标与RPC证据缺口和确定的自动操作。

验证：构造自动跳过、同牌自动弃牌、鸣牌后自动跳过、正常pass、回包早于鼠标释放、无pending、不同窗口、拒绝、缺失标记以及旧记录兼容；检查牌局事实仍由输入事件确定。实际历史只读审计自动标记和归属，新实战使用已授权一真人三电脑四人南5＋10。新报告保留所有失败，不沿用旧场宣称三整场或500窗口通过。
