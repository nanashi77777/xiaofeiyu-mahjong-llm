# 公开与私有仓库同步

2026-11-01，用户要求以后同时向公开和私有两个麻将仓库推送代码。登记DEV-083，先写方案再实现。本任务不实现另行暂缓的DEV-082重试机制。

公开origin继续只接收脱敏线性历史。私有仓库解除GitHub只读归档状态，在mirror/前缀的新分支接收完全相同的提交；原main及旧开发分支保留原始私有历史，不强推、不合并回公开仓库。私有默认分支设为mirror/main，便于首页查看最新代码。两库均仅所有者可写，私有可见性保持。

真实双库绑定保存在ignored runtime/git-sync.json，私有地址只在本机Git配置中；仓库只提交git-sync.example.json。同步工具默认读取已配置目标，在任何写入前校验全部目标的认证所有者、预期可见性、仓库ID、归档状态及分支映射。没有本机绑定的新克隆只同步自己的origin，不推断或暴露私有地址。

支持向私有库新建镜像分支并上传脱敏根提交，不重写旧分支；同一目标对象已经存在时复用，避免第二分支重复上传整条历史。所有更新force=false，读回每个分支SHA；两个仓库必须都核验成功才报告整体完成。一个失败须保留另一边实际结果，后续重跑幂等补齐，不能称原子双写，也不自动覆盖分叉。

配置默认本机当前分支与main两条分支同步，--also-main继续兼容。使用相同HEAD、相同审计和通用提交身份；每轮写入前扫描公开历史及待上传对象。私有fetch规则仅取mirror/，防止把原始私有分支带入公开工作流。

验证配置非法/仓库ID或可见性不符先拒绝，根提交/分支创建/既有对象复用、非快进和单边失败可重跑；实际读取两库映射分支哈希一致，原私有分支哈希保持。实现验证通过后消费DEV-083为完成日志，DEV-082/VAL-014继续留TODO并暂缓。

GitHub API传输复用HTTPX连接，保留默认TLS验证和本机代理环境；写请求保持间隔。上传审计使用Git批量读取对象，错误只报告固定描述、异常类型和HTTP状态，不输出API响应正文或凭据。初次同步中途失败可保留不可变对象，下一次显式运行复用这些对象；这只涉及代码发布，不实现麻将运行时重试。
