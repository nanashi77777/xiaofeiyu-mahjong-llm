# 计时、真实点击与执行确认

## 共享时间池

实战配置为 `base_seconds=5, round_bank_seconds=20`；模拟为 `5,10`。共享池随真实新小局重置，不随每次摸牌、重连或进程重启重置。

理想化累计模型是 `bank_used = Σ max(0, action_elapsed − 5)`，例如 7、8、6 秒操作消耗 6 秒。实际执行以服务器当前窗口和已校准的剩余预算为准，考虑消息接收前经过的时间、动画、网络和协议不同阶段，不能只拿本地请求时长充当全部游戏计时。

每次 deadline 取可确认的服务器窗口剩余和本地保守预算中更早的值，再减执行/网络安全余量。模型、解析、规则、纠错、界面定位和多步点击共享这个 deadline。超过 5 秒可以继续等，前提是时间池和行动窗口仍允许；窗口已关闭或预算不足就取消。

使用 monotonic 时钟计时，UTC 用于记录。记录 base/bank 原值、估算与来源、窗口开始/接收、请求、首 token、响应完成、验证、每次点击、客户端请求和服务器实际事件的时刻。执行延迟主指标到最后点击；确认延迟另列，不能把没有成功的点击计成成功操作。

性能目标沿用绝大多数操作少于 5 秒：首版观察指标为至少 95% 少于 5 秒、至少 99% 少于 8 秒，最终以 5＋10 不耗尽的模拟验证共同判断。单次分位达标不能替代整小局共享池约束。失败、重试和客户端超时事件必须单列并计入总机会数，不靠删除失败样本提高通过率。

## 必须验证的协议事实

- `GameDetailRule.time_fixed/time_add`为秒，`OptionalOperationList`同名字段为毫秒，已有当前客户端300+0和5+10真实证据。
- 当前5+10的operation.time_add已与共享池实际消耗核对；仍维护本地保守账本并取较早期限，不把新包当成共享池重置。5+20完整连续验收另行保留。
- `GameRestore.passed_waiting_time`已通过同场重载核对为秒（189与本机188.359秒），恢复窗口扣已经过时间及余量，并保留先前共享池下界，不能重放旧operation并给新满额。
- 不能根据客户端 timeuse 看起来正常就认定非超时；客户端自动摸切可能拥有正常值。是否由本执行器产生，要结合 pending 动作、实际牌与时间关系确认。

这几个事实列入 DEV-018 / VAL-001 / VAL-005。没有可信剩余时间时暂停主动输入或使用已验证的更保守剩余下界，不能冒充确定值。

## 界面定位

绑定专用浏览器进程、窗口和目标页面，建立 viewport、客户区、屏幕坐标及 DPI/缩放转换。首版控制面板提示保持前台和可见；窗口移动、尺寸变化、遮挡、标签变化后重新验证布局。

优先评估可见 UI 的只读页面几何；不可用时用手牌槽位/局部图像与按钮识别。不得因为 WS 已知手牌就盲用固定像素。重复牌、红五、摸牌槽、手牌重排、鸣牌组合和立直选牌可点击状态必须明确映射。

执行前重新取有效布局；模型调用时的旧坐标不直接使用。校验 tile/组合语义和可点击状态一致，目标窗口仍前台，操作窗口/state_version 没有过期。

布局含独立的 ui_revision 与 UIExecutionPhase。立直选牌或组合窗口打开只改变UI步骤，不能因此伪造新协议场况或使同一复合动作自动失效；真实新事件导致的state_version变化才按其窗口语义重新验证。

## 物理输入事务

一次基础点击：读取原鼠标位置 → 移动至新鲜目标坐标 → 立即按下/释放 → 恢复原位置。只保留操作系统保证输入必需的最短按键间隔，不继承参考库 majsoul_wrapper 中固定 0.3/0.5/1 秒等待。

点击期间若检测到人工移动，不强制把用户新位置拉回；发现人工出牌或接管时取消 pending 决策并暂停自动模式，保留实际状态。仅失焦时暂停输入；回到前台后校验当前窗口，旧窗口无效则丢弃，不补发历史点击。Esc/停止撤销尚未发送的输入和模型请求；已经发生的点击不能伪称撤销。

立直使用已选择的 `riichi+discard`：点击立直 → 观察进入选牌阶段 → 定位同一个约定弃牌 → 点击 → 等待真实声明/成立事件。观察 UI 转阶段不触发第二次战略选择，不能误认为手牌变化重新选另一张。

吃碰杠若有组合选择，点击按钮后定位模型已选消费组合，不自动换成赤牌组合。吃碰实际成立后再对新弃牌窗口调用模型；杠后等待真实补牌或抢杠结果。

## 确认与失败

`ExecutionReceipt` 区分 requested、validated、mouse_sent、client_observed、server_confirmed、mismatch、expired、cancelled、unknown。原始客户端出站消息仅用于证据，不代表最终成功；本家实际弃牌/副露/立直/终局事件才确认效果。

pass 可能没有独立显式成功事件，需观察对应响应提交和窗口真实关闭，标注证据等级，不编造弃牌。没有确认时不盲目重复，先同步/观察；只在确认原点击未生效、同一动作仍有效且有剩余预算时，允许一次同动作补点并单独记录。不能因为不确定就换牌。

模型格式/非法 ID/服务失败至多一次修复或重试，受同一 deadline 限制。禁止 SDK 隐式无限重试。模型合法但实际打错时保持真实场况，写 intended_action、actual_event、layout 与时间证据；旧计划撤销，下一有效窗口重新决策，不能改牌河来“匹配”模型。

结算标题可能先于可点击确认按钮出现。RoundFlow在权威round_end/ended阶段有界等待可见预检；预检未通过不记录submitted，不将该页标成已点击。只有UI在最终按压前调用before_submit才写提交记录。按压后的释放超时或场景切换结果未知时不重复点击；新局、停止或窗口变更撤销剩余流程。所有校准图仅留本机，不以标题检测冒充确认按钮可用。

## 5＋10 模拟验证

使用至少 500 个真实模型决策窗口，按来源小局聚合时间池，计入修复与实际输入耗时的已测分布/隔离窗口输入。明确区分“记录窗口的计时回放”和“真实交互整场”：离线不同选择不会凭空生成真实后续牌局，不能把固定牌谱回放当真实打完。

验证扣池、换局重置、长尾、临界余量、重连扣时、阶段多次点击与取消。另用可控延迟/错误注入验证检测和停止，注入故障预期可以失败，不能计进正常样本的零耗尽结论。正常样本耗尽即本轮验收失败，优化后保留失败报告和新的复测结果。

## 并行界面预观察

2026-10-31生产5+10首轮在第11个窗口模型超时停止；前10次均落实，但6次超过5秒。DEV-019/021继续实现只读界面预观察：模型请求期间独立识别当前完整手牌和全部已提供按钮，缓存同一对局/版本/操作窗口的可见目标，不选择或提交任何动作。后台模式仅在开始时移开游戏内部悬停指针，系统鼠标不动；预观察与输入共用租约，模型结束先取消并等待预观察释放，才允许执行模型选定动作。

点击目标缓存最多有效0.6秒，按下前仍核对原始状态、布局和1.2秒总新鲜度；过期、缺失或预观察失败立即走完整识别路径。立直选牌和多组合弹窗必须在相应按钮真实打开后重新识别，不能预造弹窗。2026-10-31用户新增流式输出提交方案后，完整有效的首动作段可按[流式动作契约](streaming-action.md)先执行，解释及计划延后接收。

手牌位置有独立的事件和可见像素缓存：等待他家时提前识别，手牌、小局、摸牌槽或副露变化会失效；新截图归一化后的手牌区域逐像素一致才复用原实例映射，布局/缩放或像素变化重新核验。位置缓存不等于有效点击目标，不刷新旧目标的observed时间。空闲预观察与实时观察、实际输入共用租约；停止或新窗口先等待已有只读任务释放。记录缓存命中和识别/输入分段时间，以实测判断收益。
