# 有限重试与错误恢复

2026-11-01最新授权：用户要求“把重试机制先做出来”，解除原先暂缓，优先实施DEV-082，VAL-014独立验收。以下为编码前确定的实施方案；完成情况由注册表和完成日志给出。

DEV-055中既有的鸣牌未提交诊断保留原记录，其涉及的有限恢复部分统一归入DEV-082。

目标是让可恢复的单次错误进入有限恢复流程，保留真实失败及原始证据；人工停止、事实不可信和输入结果未知等情况仍按风险暂停。模型继续决定全部主动打牌选择，恢复逻辑不得自行选牌或篡改实际牌局。

按失败阶段处理：

- 模型网络/服务/格式错误：统一管理现有纠错和新重试的总次数，避免外层重试叠加内部重试。每次带完整当前上下文、独立请求标识，旧请求取消；仅在同一有效操作及原始截止仍允许时重试。所有实际usage分别记账，未知仍为未知。
- 流式首动作已接受或已经输入后，解释/计划尾段失败只标注附加信息缺失，不重发已接受的决策或点击；恢复管理器必须与现有首动作提交点共享状态。
- 按下前定位或动画暂态：重取新帧、核对实际状态及同一模型已选动作，有限次重新定位；不能把换组、换赤牌或换弃牌当重试。状态或合法候选变化后交由新窗口重新调用模型。
- 已按下但确认迟到/结果未知：先只读观察客户端及服务器真实事件。未证明确实没有提交之前不得补点；立直两步、鸣牌组合和结算阶段分别记录已完成阶段，禁止重复副作用。
- 连接/状态恢复：有界等待客户端重连和真实同步，以真实恢复数据重新建立事实、时间和当前窗口；旧动作不重放、时间池不重置。只有新鲜且一致的窗口才能重新接管。

所有尝试共享原始deadline和本小局剩余时间池，保留点击余量。配置默认模型总尝试2次（含已有修复和可选竞速）、每个语义点击阶段最多2次重新定位（共3次），连接恢复只读等待2轮、每轮5秒，连续3个不同窗口失败熔断。模型429/5xx/网络/格式错误允许重试；鉴权/其他永久HTTP错误立即暂停。每次失败原样保留，短退避不超过剩余期限，不能重置时间池。客户端自己负责连接重建，本实现只观察真实同步，不主动刷新页面或重放输入；两轮仍无真实恢复即暂停。超时不发本地策略动作，窗口失效则记失败并观察下一真实有效窗口。

实施顺序（DEV-082）：①配置、窗口去重失败/连续失败状态机与审计事件；②模型统一尝试和错误分类，前缀提交后的尾段永不重发；③原生/浏览器按下回调及单层定位重试，立直/组合分别记阶段且不重按；④协调器区分未按下失败、可能提交等待、下一新窗口、断线只读等待及停止取消；⑤故障注入、全量回归、隐私审计、双仓库同步。已按下异常保留pending，仅等实际回执/事件，确认等待有界（默认2秒，仅观察，绝不延长原窗口输入截止），未确认则暂停；真实不匹配仍立即暂停。历史任务完成日志保留其当时暂缓事实，不改写历史结论。

需要定义窗口级失败、软恢复等待、连续失败熔断和必须人工处理的暂停。建议连续3个窗口失败进入暂停；同一次故障不能重复累计。用户停止/Esc、窗口绑定改变、事实缺口、真实意图偏差或未知已提交输入必须优先取消恢复，不能由旧异步任务自动重新启用。恢复等待期间仍记录真实牌局；客户端自动摸切不能记为AI成功。

新增可追溯attempt/recovery事件：原故障、原窗口、已提交阶段、次数、剩余时间、实际确认、恢复结果和后续动作关联；QQ仅通过已有只读接口按需获取状态。原始失败、恢复成功率与恢复耗时分别统计，不删除失败或把旧正式失败场改成合格场。

DEV-082实现时须先补状态机和配置，再做错误注入/竞态/幂等测试。VAL-014单独检验429/5xx/断流/非法输出、动画与目标过期、按下后迟确认、立直与多组合、断线恢复、停止竞态和耗尽；随后独立真实5＋10试验，保留所有尝试/耗时/用量，完整整场与500窗口仍按原VAL计数。
