# 流式动作提交与延后解释

日期：2026-10-31（Asia/Shanghai）。用户提出并授权在当前开发中采用流式输出提前执行合法动作。

流式开关为stream_actions，格式由stream_action_format选择。nested兼容格式为 `{"d":{"q":"本次请求标识","a":"合法动作ID"},"r":"简短解释","p":null或计划}`；short精简格式为 `{"a":"合法动作ID","r":"简短解释","p":null或计划}`。两种格式的首字段完整闭合、且其后出现JSON字段分隔符时为动作提交点；不能按单个token、未闭合字符串、正则匹配动作名或后续解释中的动作名点击。nested的d仅允许q/a；short由本机独立请求绑定q并还原领域决策，不要求模型回显随机标识。两者均拒绝重复键、未知候选和动作改写；完整尾段还必须符合本请求动态Schema，提交后任何尾段错误只记解释失败，不再点击或请求第二个动作。

仍须在执行前核对权威match/version/window、统一截止、停止与界面新鲜度，先取消只读预观察并释放输入租约，才能执行同一模型动作。模型不得直接修改状态。实际服务器事件保持唯一真相。

动作提交后网络接收在有界后台任务中继续，不因正常弃牌确认或下一事件取消解释；新鲜决策优先。解释及本小局计划完整解析、请求匹配、计划依据校验后追加到原动作记录的读取投影，不重复增加决策数。计划只在实际确认、同一小局且原计划版本仍一致时采用；迟到计划不能覆盖新版本或新小局。日志记录动作可用耗时、点击耗时、完整响应耗时、usage及解释状态；流中断usage未知不能写0。

动作提交前错误按原有限纠错规则；提交后流中断不重发游戏输入，不影响已确认实际结果，单独记录解释缺失。用户停止/服务退出取消后台任务且禁止后续点击。不要求或保存模型私有思维链，仅保存简短可展示解释与结构化打法计划。

验证覆盖任意字符分片、Unicode、字段分隔符、非法/重复/改写动作、尾段断流、停止/过期、服务事件先于尾段、迟到计划与新小局，以及指定模型实际Schema/none/usage和端到端差值。首字延迟不能因这项优化消失；正式五秒验收仍按真实读取至点击计算。

2026-10-31实际模型探针各10次，归档局面相同且推理token为0。nested无计划更新的两次完整输出为41/42 token；short无计划更新的五次为34/34/34/35/36 token，输入中位从12325降为12223。两批计划更新频率和调用时段不同，不能比较总体输出中位来声称固定节省比例，也不能把动作可用中位5031.5ms与3859.5ms之差全归因于格式；short仍出现10秒以上TTFT。报告保留在本机runtime/stream-prefix-probe-v1.json和stream-prefix-short-probe-v1.json。实际5+10实战另行记录，模型探针不算真实游戏窗口。

输出已经接近所需契约的精简形式，但未证明全局最优。a是本机映射到完整合法操作和具体手牌实例的短ID，r只记录可展示的简短理由，p不变时为null；有新依据才输出完整计划。不能为少数字符丢掉合法性、当前小局计划或事实依据。计划可能在点击后才写完；新窗口只使用已完整校验和确认采用的计划。
