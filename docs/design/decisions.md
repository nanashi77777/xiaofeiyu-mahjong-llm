# 已确认的设计选择

来源：2026-10-30 用户四轮 grilling 回答。以下选择已逐项确定；整体文档仍待用户确认是否准确表达共同理解。

| 问题 | 已定选择 |
| --- | --- |
| Q1 纯大模型边界 | 本地只做规则和确定性事实计算，不提供传统策略推荐/评分/排序，不排除合法但不推荐的动作；主动选择全部由模型做 |
| Q2 时延取舍 | 允许极少短暂超五秒，继续等模型，不用本地策略兜底；固定 your-model-id、推理关闭 |
| Q3 运行载体 | 单专用 Chrome/Edge 浏览器窗口，CDP 读取 WS，真实鼠标点击 |
| Q4 对局范围 | 标准四麻，四人南优先，兼容标准四人规则变化；用户登录入桌并开启，正常局间继续、终场停，不自动匹配；未打满也保存 |
| Q5 成绩目标 | 最终顺位及避免第四优先，点差下兼顾打点、速度与防守；允许弃和 |
| Q6 费用 | 无固定预算、不做预算限制，逐请求记录 token 消耗 |
| Q7 二十局口径 | 最近二十场完整对局身份，不是二十小局；展开场内小局，底层保留历史 |
| Q8 大牌 | 默认本家跳满及以上；按和牌等级，不按含本场/供托到账额；保存四家实际结果供复盘 |
| Q9 QQ 方式 | 按需调用查询接口，不在每次对话访问，不主动播报；默认不公开当前手牌和未执行计划 |
| Q10 时间池 | 实战5秒基础＋每小局共享20秒；模拟5＋10，验收要求不耗尽；不能只看单次分位 |
| Q11 前台 | 首版游戏保持前台，失焦暂停输入；采集和查询继续 |
| Q12 自主学习权限 | 可改经验和结构化风格，不改代码、规则、核心提示词；修订/停用可审计 |
| Q13 中断计数 | 最近二十场包含进行中/结束/中断，真实终场与最后观察点数分开；同场恢复合并 |
| Q14 历史起点 | 新服务运行后积累，预留导入，不要求首版补齐此前二十场或搬旧视觉历史 |
| Q15 模型/执行失败 | 同期限最多一次模型修复/重试；实际输入偏差以实际事件为准、撤销旧决策；不默认换牌 |
| Q16 本机入口 | 本机网页面板，可控开始/暂停/停止，查看场况、解释、计量、历史和经验 |
| Q17 实时与复盘 | 一次实时结构化输出提取动作/解释/必要小局思路；整场结束或中断后异步复盘，新经验下一场使用 |
| Q17 追加要求 | 小局思路必须具体，例如接近某役、领先速攻、推进失败/威胁升高转守；目标/依据/转向条件结构化 |
| Q18 经验可靠性 | 候选可少量带标签召回；至少后续三场独立复核并查反例才考虑稳定；确定错误可立即更正/停用 |
| Q19 唯一动作 | 仍需客户端输入时，即使仅一个合法候选也调模型；无本家窗口和客户端被迫自动动作只记录 |
| Q20 验收 | 特殊事件/隔离点击专项，至少500真实模型窗口5＋10零耗尽，三场完整AI友人四南，另测中断恢复、QQ和经验 |
| 补充 Git | 单独目录与独立 Git，创建用户自己的新私人 GitHub 仓库并上传；授权已给，不重复索取上传许可 |
| 补充 TODO | 先完整方案后代码；TODO完成后转开发日志，已开发功能不能仍作为未开发总方案挂起 |
| 补充输入模式 | WS增量归并到本地完整状态；每次独立请求模型并提供完整当前决策上下文，不依赖上次对话 |
| 补充token优化 | 保留打牌信息与全部合法动作，通过紧凑投影/公共字段/共享特征/短引用降低重复；信息等价与真实模型理解配对通过后才启用 |
| 补充役种表 | 维护版本化役种参考表，完整表不在每次实时决策附送；复盘/经验迭代按需读取，实时仅提供当前相关役种条件与无役风险 |

## 工程默认值

独立目录 `<project-root>`，拟仓库名 `xiaofeiyu-mahjong-llm`；Python 核心、SQLite WAL、Playwright/CDP、Windows SendInput、loopback HTTP面板与查询、小型Node MCP适配器。它们是实现方向，不是已经存在的程序。

仅失焦暂停输入，回前台先重校验窗口；人工出牌或明显接管撤销 pending 并暂停自动模式，避免争抢。用户在输入瞬间移动鼠标时保留其新位置。历史默认不自动删除；原始运行证据本机保存，后续需要清理策略时另行提出，不能为节省存储自动删牌谱或经验审计。

当前局计划在新小局重置；经验集合在新场边界确定，活动场不被异步新复盘悄悄改长期依据。模型计划转向条件只供模型使用，不让执行器自动做策略决定。

## 尚待查证的事实，不是用户偏好

1. 当前雀魂协议/解码、不同 operation 的 combination 语义、重连载荷与事件顺序。
2. time_fixed/time_add 的实际单位、附加时间剩余池语义、恢复经过时间与时钟校准。
3. 渠道JSON Schema/流/取消/usage/输出上限兼容性及真实长尾时延。
4. 页面可见几何能否稳定定位手牌/按钮，必要的局部CV与DPI映射效果。
5. 本机GitHub认证/CLI方式、新远端可用名称、账号和private属性。
6. 标准四人规则矩阵和计算库的实际覆盖、外部代码的逐文件许可。

这些进入对应 DEV/VAL 任务，通过检查与实验解决，不凭猜测宣称支持。提供的密钥仅用于未来本机私密配置，没有放进本设计稿。
