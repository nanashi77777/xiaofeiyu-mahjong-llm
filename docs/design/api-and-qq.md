# 本机查询、QQ 与角色连续性

## 边界

麻将服务保管客观牌谱、成绩、经验与计量，监听 `127.0.0.1`。QQ 使用一个小型 stdio MCP 适配器按需查询，只读凭据与控制凭据分开；启动/停止、窗口绑定和经验修改不进入 QQ 工具目录。

2026-10-31用户新增QQ选场授权：mahjong_navigate/mahjong_navigation使用第三类独立导航令牌，访问/api/v1/mahjong/navigation的规范命令、进度、取消和续跑路由。QQ不持有通用控制凭据；本轮真实消息生成幂等ID，沿用当前会话白名单。登录/选段位/加入/建房的契约与实际进度见lobby-automation.md；原查询接口和活动暗手保护保持有效。

本机面板可以查看自己手牌、计划与调试信息；QQ 的默认投影不公开当前手牌和未执行策略。公开查询不返回对手账号标识、认证信息、原始网络包、文件系统任意路径或运行错误栈。

## 拟定 HTTP 查询契约

| 路径 | 查询与返回 |
| --- | --- |
| `GET /api/v1/mahjong/live` | 活动/恢复/中断状态、freshness、场风局数本场、供托、点数、顺位、场次类别 |
| `GET /api/v1/mahjong/matches` | 最近二十场，支持 status/completeness 筛选与游标；不是二十小局 |
| `GET /api/v1/mahjong/matches/{id}` | 场概要、真实终场或最后观察状态、小局索引、来源与记录范围 |
| `GET /api/v1/mahjong/rounds/{id}` | 已结束小局的结构化事件、模型简短解释和结果；对活动小局按 QQ 投影隐藏暗手、计划及可能泄露它们的自由文本 |
| `GET /api/v1/mahjong/big-hands` | 固定最近二十场集合中的本家跳满及以上，带 match/round 外键、役种、番符、和牌方式与点数 |
| `GET /api/v1/mahjong/memories` | 关键词/条件/状态查询，候选/稳定/停用标签及证据摘要 |
| `GET /api/v1/mahjong/memories/{id}` | 当前修订、历史、来源范围与更正/停用原因 |

共用响应带 schema_version、as_of、source、freshness、completeness、data、next_cursor；空结果与服务不可用分开。错误只给简短可理解状态，内部细节留本机。列表有参数校验与最大返回量，牌谱详情分页，不一次将所有档案塞给 QQ。

当前小局的 reason、计划依据、复盘片段等自由文本可能间接泄露手牌；QQ 投影默认整段不返回，不能只删除 hand 字段。历史查询和经验引用也必须应用相同活动局过滤。面板可显示完整本家信息；已结束小局的历史解释按查询需求提供。

实现归属：DEV-022 完成战况/历史/大牌路由，DEV-026 完成经验只读路由；DEV-023 在两者可用后一次挂载完整四类 QQ 工具，不把未实现的经验工具标作已经集成。

最近二十场按最近观察时间排序、match_id 去重，包含 active/ended/interrupted；当前场还可单独 live 查询。查询开始时固定这二十个 ID 集合，后续分页和大牌查询用同一范围标识，避免新场插入导致前后范围不一致。

大牌按实际和牌等级而非本场/供托到账金额判定。优先服务端等级；无等级时用真实番符及房间役满规则确定，不确定则明确标未知，不把普通满贯加本场算成跳满。本家每次和牌独立保存，多家和牌不能串到其他玩家。

实时顺位由真实点数与房间同点顺序计算并注明依据；最终顺位只取终场或已核实的结算规则。友人/段位/其他/unknown 从 game_config 元数据推导，未知不能默认段位。

## 拟定 QQ 工具

DEV-063扩展现有响应，不增加QQ入口：已结束小局的wins及整场小局索引提供结构化和牌归属；整场win_summary提供本家荣和、自摸、放铳事件数、被荣和人数及来源未知数量。big-hands沿用原有字段并补充和牌张/来源引用。座位均为服务器绝对0..3，以self_seat识别本家，不能把自摸付款或包牌当放铳。活动小局保持原有暗手保护，未知来源不虚构为确定座位。

归属项的稳定id为原和牌event_id加冒号及和牌者索引。kind取ron/tsumo；source_kind取discard/draw/initial_deal/kakan/ankan；source_status取confirmed/unknown/conflict。只有confirmed的荣和from_seat可计放铳。source_status非confirmed时source_event_id如存在仅为待核对来源，issues解释缺失/冲突，不可当确定证据。tile保留实际0赤牌，未观察到则null；暗杠牌种相同但赤色未知时不猜具体五。win_summary.unattributed_ron统计全场归属未确认的荣和人数，不能假定其都由本家放铳。查询分页只影响events，wins是该小局完整结果，不依赖当前页是否含和牌事件。

初始提供四个业务入口，避免工具目录膨胀：

- `mahjong_live()`：当前战况。
- `mahjong_history(kind, id?, cursor?, status?)`：最近对局、整场/小局详情。
- `mahjong_big_hands(scope_cursor?, cursor?)`：最近二十场内的大牌。
- `mahjong_memories(query?, id?, status?)`：打法经验与修订依据。

工具返回经过投影的结构化数据。QQ 仅在用户谈及/询问麻将且确有信息需要时调用，不每轮自动访问、不自动定时播报。当前所有白名单规则、群触发规则和发送权限保留，不主动发送测试消息。

在 `<qq-project>` 注册工具和小段麻将查询说明，复用其现有真实经历表达约定。不要把麻将学习写入需要真实用户记忆意图的 qq_memory_* 人际记忆接口。修改后按该仓库约定运行 `npm run test-qq`、暂存秘密审计，并在无在途回合时处理必须的重启。

## 让经历属于同一个角色

小肥鱼使用同一角色身份和语言风格，查询真实牌谱后用第一人称表达：“我刚才南二那把保位没推”“最近在尝试有役保障再提速”。事件摘要、当时解释和长期经验都有可核对依据；不虚构和牌、真人身份或未发生的操作。

实时打法不加载 QQ 长对话；角色连续性来自稳定人格摘要、真实成绩/经历、风格和经验，不能通过共享群聊/私信原文形成。QQ 可以说“我正在试这个思路”，但候选经验不能讲成已经证明正确的结论。

## 面板

本机面板提供专用浏览器连接/窗口绑定、开始/暂停/停止、Esc 状态、当前局点数与手牌、当前计划、最近意图/实际动作、耗时/共享池/token、历史和记忆查看。开始接管前显示当前连接和规则支持情况；状态异常不伪装正在正常打牌。

面板修改控制必须鉴权、校验 Origin/CSRF；只监听 loopback 不等于网页跨站请求天然安全。QQ 查询令牌不能调用面板控制。服务不可用时 QQ 简短说明暂无实时信息，不能拿旧记录冒充正在打。
