# 合法动作与确定性特征

## 合法性权威

操作窗口来自服务器候选；本地规则与真实房间选项补全弃牌、消费组合和阶段约束并交叉验证。二者不一致时保留原始证据、请求同步或暂停，不能用传统策略静默裁剪候选。

`operationList.combination` 按操作类型分别解释。吃/碰可能是消费组合；弃牌阶段可能是吃替禁打列表。旧示例支持这种差异，但当前客户端真实载荷仍须验证。不同消息的 type 数字不是同一套枚举；领域层使用明确 action_kind/meld_kind。

必须覆盖：普通弃牌、立直绑定弃牌、吃、碰、大明杠、暗杠、加杠、自摸、荣和、跳过和可选九种九牌等标准规则操作。自动优先和牌、自动跳过、自动选红牌或“无役风险所以禁止鸣牌”都不属于合法性逻辑。

## LegalAction 契约

动作含 action_id、operation_window_id、based_on_state_version、kind、actor、tile/hand_tile_id、drawn_discard、consumed_tiles、source_discard、meld_id、ui_steps 和 features。action_id 仅在当前窗口/状态有效，模型只返回 ID，不自造坐标或牌。

立直候选是 `riichi + 确定弃牌`；点击分两步但战略决定一次完成。吃碰候选是确定消费组合；吃碰后实际新窗口的弃牌仍由模型选择，不能预先默认跟一张“最佳弃牌”。杠只决定宣告具体杠，补牌后产生新决策。跳过也保存为决策，因为可能影响振听。

规则层完整列出合法动作，按稳定的规则顺序展示，例如 kind 和牌编码顺序，而非推荐度。不能先按进张、危险度或收益筛掉候选。必要的去重仅合并语义完全相同的动作；保留红五/普通五和摸切区别。

## 向听和进张

- 同时支持通常型、七对、国士，副露与门清状态正确进入计算；和牌可标 -1，听牌 0。
- 当前向听必须带 hand_phase 与 concealed_count，不能拿不同阶段数值直接当等价牌形比较。
- 普通弃牌/立直：给出确定弃牌后的向听、进张牌种、基于本家可见牌计算的剩余枚数；不把可见剩余数称作真实牌山数量。
- 吃/碰：给出固定组合形成后的 awaiting_discard 阶段，以及后续合法弃牌的向听映射；未完成弃牌不能伪装成已选好弃牌后的单一数值。未来服务端限制尚未获得时标明本地推导/待确认。
- 杠：给出已固定面子变化与 awaiting_replacement 阶段。补牌未知时，补牌后的确定向听为 null，不能假装岭上牌已经到手。
- 跳过：牌形通常不变，另列潜在振听与响应窗口关闭等后果。
- 自摸/荣和：给终止结果与算点，不强行用普通弃牌后的向听表示。

每个动作的 features 都带结果阶段、确定性与未知项；模型能明确比较当前状态和该动作真正可确定的后果。

## 役种与得点

维护[独立役种表](../../reference/yaku/standard-four-player.v1.md)，作为复盘和经验迭代的按需参考，不在每次实时决策附全表。该表是版本化知识资料，不代替执行中的规则计算；使用与更正规则见[参考表设计](yaku-reference.md)。

分成三种信息，防止把“接近某役”说成“已经有役”：

1. 已完成和牌的真实役、番符、基本点与支付额：优先保留服务器结果，本地算点用于选择前估算和交叉核对。
2. 听牌的逐张待牌价值：按荣和/自摸、立直、振听、门清食下、宝牌赤牌与真实房间选项计算。宝牌本身不构成役。
3. 未完成手牌的可能路线：确定的牌面特征、必要条件与阻碍，例如有两组役牌对子、染手花色比例、门清是否仍可维持。路线标 conditional/unknown，不能承诺未来一定达成。

区分临时过和振听、舍牌振听、立直后过和振听；单个服务端布尔字段不足时结合可知事件，并保留未知，最终以实际可操作候选约束。涵盖一发消失、抢杠、岭上、海底河底等上下文。

对手现物、公开牌、宣言时点、点差和当前排名等可以作为可核实事实；危险概率、胜率预测、传统 AI 综合评分或收益排名不进入首版规则层。

## 主动与客户端行为

所有仍需要主动输入的打牌动作均请求模型，即使只剩一个合法候选。没有本家操作窗口时不请求；客户端自动的立直后被迫摸切记录为 client_forced_action。若立直后出现自摸/暗杠等提示，仍请求模型，放弃时执行跳过。

普通界面结算确认不是麻将策略选择，可由已确认流程点击；不进入新场匹配。超时或服务故障时没有规则策略接管。
