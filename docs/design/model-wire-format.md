# 独立完整决策请求的紧凑结构

日期：2026-10-30。用户已确认数据模式为“WebSocket增量接收 → 本地维护完整状态 → 每次独立请求模型，携带本次完整决策上下文”，并要求在不影响打牌效果的前提下减少token。本文件是拟实现契约，没有运行中的编码器或实测节省结论。

## 两层结构

持久化领域模型继续采用清晰、完整、版本化字段，保存事件证据、长ID、模型选择、UI步骤与输入回执。新增独立的模型请求投影：只转换表达与引用，不改变实际状态、合法动作和确定性特征。

独立请求不使用之前对话或上次响应作为隐含依赖。每次包含固定的字段/动作说明、真实生效的规则配置、本次场况、完整合法动作、当前计划与必要经验。固定说明属于本次输入token；可能的渠道缓存只单独计量，不能把它当成免费或保证命中。

独立完整上下文不要求每次带麻将教材。[役种表](yaku-reference.md)留给复盘与自我迭代按需检索，完整表及无关定义不进入实时固定前缀；当前手牌/动作相关的役、门清食下条件和无役风险仍明确提供。

## 默认压缩方式

| 重复来源 | 处理 | 必须保留的语义 |
| --- | --- | --- |
| 每个动作重复的窗口/状态/操作者 | 提到请求顶层，本机保留长ID映射 | 请求、窗口、状态、账号座位仍被可靠绑定 |
| 每个动作重复当前向听/点数/规则 | 放公共场况一次 | 所有候选仍在相同事实基准下比较 |
| 同样的动作后特征 | feature表共享引用 | 仅完全相等的特征对象可共用，不合并不同动作 |
| UI坐标、截图路径、协议原包、输入步骤 | 不进入策略请求，留执行器/档案 | 模型选择仍绑定准确牌实例、红牌和消费组合 |
| 反复描述宝牌、进张、点差的自然语言 | 使用明确的结构化值一次 | 已有事实计算仍提供；不强迫模型重算规则 |
| schema版本与每行相同的字段名 | 顶层版本、固定列定义和四列动作表 | 单一版本中列序不变，边界与null含义明确 |
| 毫秒时间戳、长UUID | 请求使用局部序号和短引用，本机可逆映射 | 全局事件先后、过期校验、证据链接不丢失 |
| 每次复述相同打法计划 | 本次仅传当前有效完整计划 | 独立请求不能仅传“计划未变”，让模型猜上次内容 |

不假设字母越少token一定越少。场况字段保留易懂的英文名称，例如hand、scores、rivers、melds；牌保留1m/0p/7z，不用生僻编码、base64、位图或压缩文本。短别名仅用于高频重复项，最终以指定渠道usage实测净收益。

## 请求顶层

下表为请求投影的字段契约；不是把领域模型替换成这些字段。

| 字段 | 含义 |
| --- | --- |
| v | wire格式版本，例如mj.wire.1；解码器/固定说明同步版本 |
| q | 不复用的短请求标识；本机绑定原match/round/state/window与完整输入哈希 |
| rules | 当前真实规则的紧凑投影；可引用本次固定前缀内的标准profile，并显式覆盖差异 |
| seats | 本次座位约定、庄家、本家自风和同点顺序依据 |
| round | 场风、局数、本场、供托、余牌、当前权威阶段 |
| scores / ranks | 四家实际分数及顺位；未知为null，计算依据保留 |
| hand / draw | hand数组元素保留逻辑牌实例顺序，索引作本请求局部牌引用；draw是摸牌索引或null |
| dora | 当前已揭示的有序宝牌指示牌，重复项保留 |
| rivers | 四家完整有序牌河，含tile、全局事件序号、摸切/立直声明/被鸣走等属性 |
| melds | 四家副露，含类型、牌、来源/消费牌、原弃牌引用和事件序号；加杠关联原碰 |
| riichi / furiten / context | 声明与成立、可知振听、海底/岭上/抢杠等规则上下文和未知项 |
| clock | 本次剩余基础/共享时间、保守deadline与确定程度，不为省字丢执行预算 |
| shanten | 本家当前向听及所对应阶段 |
| offer | 当前响应牌、来源玩家与事件引用；没有时为null |
| actions / features | 所有合法动作与共享的确定性特征 |
| plan | 当前小局有效计划完整内容及版本；没有为null |
| memories | 少量相关经验的主张、适用条件、candidate/stable标签、修订与证据摘要 |

字段之间不能以“可以推导”作为删除已有有用信息的理由。例如当前顺位、向听、确定的役种条件仍直接提供，不把计算工作转回关闭推理的模型。

## 动作表

每行固定四列：`[id, kind, args, feature_ref]`。列说明写入本次请求的固定前缀。id采用a0/a1等局部短字符串，在本请求内唯一且一一映射本地完整LegalAction；不同请求相同a0不代表同一动作。

kind采用可读名称，如discard、riichi、chi、pon、daiminkan、ankan、kakan、tsumo、ron、pass、abort9，不要求模型背无语义数字。

| kind | args含义 |
| --- | --- |
| discard / riichi | hand中的牌实例索引；riichi已经绑定该弃牌；是否摸切由draw和索引明确，执行前再次核对 |
| chi / pon / daiminkan / ankan | 消费牌索引数组，offer/现有状态提供叫入牌；四个索引的暗杠不能与明杠混同 |
| kakan | 可读对象，明确已有碰的副露引用和新增牌索引 |
| tsumo / ron / pass / abort9 | 不需要额外参数时为null；和牌/过和结果由feature描述 |

下面只展示一个摸牌窗口中“打出普通五”和“摸切赤五”的两个动作片段，**不是完整请求或完整合法动作集合**。draw=13，hand[4]=5p，hand[13]=0p；f0/f1是同请求内完整特征对象的引用。

```json
{
  "draw": 13,
  "actions": [
    ["a0", "discard", 4, "f0"],
    ["a1", "discard", 13, "f1"]
  ]
}
```

两者即使向听相同，赤牌留手、得点和摸切可观察效果也可能不同，必须分别保留。重复普通牌的物理索引也不能因为短表而丢失；是否合并语义完全相同的候选仍按规则层契约处理，不由压缩器擅自决定。

## 特征共享与阶段

features是请求内字典，键如f0/f1，值仍用明确字段表达after_phase、shanten、ukeire、yaku、furiten_change等。相同的特征对象可以复用，但等价判断需包括全部字段、确定性、红牌价值、未知项和阶段，不能只比较向听数。

- 弃牌和立直的后状态确定，保留通常/七对/国士及已承诺提供的进张/役种信息。
- 吃碰的特征包括待弃牌阶段与后续合法弃牌分析映射，不能只传最低向听来代替全部选项。
- 杠的补牌仍未知，after_phase为待补牌，补牌后shanten保持null，不能为了填满同列而编数。
- 和牌动作是终止结果；跳过可能改变振听。保持类型，不把所有特征挤成一个无语义分数。

规则层仍列出全部合法动作，按稳定非策略顺序。压缩后不能选top-k、合并红五/普通五、舍去pass或按收益排序。

## 行动历史与可追溯

当前小局的四家牌河每次完整传输，不能只保留最近N张。每项保留全局单调事件序号；叫入牌引用牌河原事件，消费牌和副露类型仍可读。跨玩家行动先后、立直声明与成立、杠/宝牌时点、一发中断、过和/临时振听等信息必须存在于结构中。

必要公共时序采用带类型的事件引用/摘要，引用本次已有牌河或副露事实，避免同一弃牌再写一遍长自然语言。不通过无约束模型总结替代原事实，不截断影响防守和合法性的早期事件。若跨表引用让模型理解下降，保留更直观的重复表达。

长事件ID在本机有映射；模型plan_update的basis_event_ids可使用本次短引用，程序验证存在后恢复为真实ID。仅对本请求事实做引用，不能靠外部字典或上次上下文补全。

## 输出

沿用已设计的action_id/reason/plan_update字段，另回显q。action_id用本次a0/a1映射，服务器不接受跨请求ID。q不是唯一防线：协调器同时核对原请求上下文、窗口、真实状态、截止时间和输入布局。

```json
{
  "q": "k4",
  "action_id": "a0",
  "reason": "保留赤五，维持当前役种路线。",
  "plan_update": null
}
```

例中理由仅示意结构，不代表某个真实牌局的策略建议。q不匹配或不存在的action_id都拒绝执行；仍按最多一次且在期限内的纠错约定处理。解释保留简短句，具体打法计划仅在变化时输出，无变化时null；不为省输出token删掉已要求的解释。

当前计划在每个独立输入仍要完整传回。计划若更新仍使用完整结构化对象，不改成跨调用JSON补丁链。领域归档恢复长action_id和真实basis事件，使QQ与复盘不必理解wire短编号。

## 两层验证和启用条件

1. **信息等价验证：**丰富格式与紧凑投影均映射到相同的“模型应知事实”集合。检查所有合法动作ID/消费牌/特征一致、牌/时序/规则/未知值/计划/经验标签无遗漏。此处等价只针对模型决策信息；UI坐标、认证载荷和调试字段本来不应提供。
2. **模型理解验证：**固定同一模型、none、局面与记忆，用丰富格式/紧凑格式做配对对照。计入固定说明开销；记录真实input/output/cached token、完整延迟、格式/非法ID/引用错误，复核红牌、振听、无役、吃替、立直/杠阶段、攻守转向和点差等关键判断。

合法多解局面不要求每次动作一致；对变化动作检查事实理解和选择理由，不用另一套传统AI的推荐充当真值，也不凭一次输赢判定效果。选择有歧义的样本多次对照，报告分歧与不确定性。配对比较通过不代表已统计证明长期顺位不下降，最终仍须完整实战验收。

结构错位、关键理解回退或净token无收益时回退到丰富但已去除无关字段的格式。不要为追求压缩比例保留可疑编码。使用字段名精简/去重复的保守层作为基线，动作矩阵与共享引用属于需要单独验证的优化层。
