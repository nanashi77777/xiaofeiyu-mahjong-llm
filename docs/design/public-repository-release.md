# 公开仓库与隐私发布方案

2026-11-01，用户授权公开麻将仓库，公众可读取和克隆，不能取得写入权限；公开内容不得包含个人信息或敏感配置。登记DEV-081，在实施前明确以下顺序。

1. 在本机被忽略目录保存原Git bundle与远端元数据，原运行配置和服务不变。核对所有远端分支、标签、协作者、邀请、部署密钥、PR/issue/release/Actions附件及Wiki/Pages，不能只审计当前工作树。
2. 当前文件和所有历史版本移除私人邮箱/作者身份、实际模型/渠道/配置、本机工作目录、真实测试房号与牌局标识。以通用贡献者身份重建提交，保留开发顺序、时间、内容和任务关联；历史中的提交引用按映射更新，映射原文只留本机。第三方公开出处与必要许可证署名保持。
3. 原GitHub仓库始终私有并改名归档，公开地址使用新仓库存放脱敏后的历史。这样公开仓库不接收原始Git对象，避免仅强推后旧对象仍可能通过旧SHA访问。不存在需要迁移的公开讨论内容时采用此流程；原库不删除。
4. 新仓库先私有：逐对象检查全部历史、鉴权读回内容、检查代码和任务视图，上传并核验每个分支SHA；确认只有仓库所有者可写、无协作者邀请/写部署密钥，自动工作流令牌只读。最后才将其设为公开，再独立验证匿名读取与旧对象不可访问。普通公众不能直接push；fork不获得源仓库权限。
5. 同步工具从远端核对所有权、适配授权公开仓库，继续非强制更新和上传审计；安装本机提交检查，未来提交使用通用身份。完成记录写实际检查结果、当前公开地址、已改变的提交哈希及私有归档说明，消费TODO。该任务不改变麻将决策配置、不重启服务，也不把仍未通过的实战验收写为完成。

公开账号名称及项目地址属于用户主动选择的发布身份；第三方开源引用和许可证为必要公开归属，不能伪造或删除。自动扫描不能保证识别任意未知秘密，发布前另做文件种类/内容复核并保留本机证据。
