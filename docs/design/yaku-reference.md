# 役种表与自我迭代参考

日期：2026-10-30。用户要求维护役种表，不在每次实时决策中附全表，供自我迭代参考。

## 参考资料与实时事实

役种参考数据放在`reference/yaku/standard-four-player.v1.json`，可读视图为同目录Markdown。它是可版本控制的公共规则知识，不是账号数据或麻将经验库。字段覆盖稳定ID、中文名/别名、分类、门清/副露番数或役满倍数、成役条件、可否鸣牌、互斥/包含关系、房间规则差异和来源。

完整参考表不放入实时system prompt、固定前缀或每次用户请求；也不为实时模型注册需要额外网络调用的役种查询工具。紧凑输入的固定前缀只保留格式解释与必要通用约束，不夹带整份役种教材。

实时规则层仍给出当前牌和每个合法动作真正相关的事实：已成立役、听牌的待牌/番符/得点、门清和食下条件、可能路线的必要条件与无役风险。可附稳定yaku ID及简短名称，模型不必仅凭陌生ID回忆。宝牌不构成役、当前副露是否失去门清资格等决策关键内容不能因为“参考表另存”而省略。

## 复盘与迭代的读取

复盘可按牌谱实际役、模型当时计划、无役判断错误或出现争议的概念检索参考表。默认只取相关条目及必要的包含/互斥项；需要系统整理打法时可以读取更大范围或全表，不要求每次复盘都附全表。

已实现内部只读能力`read_yaku_reference(ids?, topic?, all_entries?)`，仅供复盘/经验整理流程调用。返回catalog_version、匹配条目、依赖/排除项和来源；真实房规同时随复盘的match.rules提供，不从参考表推测。未知ID明确失败。实时打牌流程不等待该查询，QQ无需新增这项工具。DEV-031记录生产复盘加载；[VAL-011](../development/completed/VAL-011-yaku-reference.md)补充指定模型真实渠道的查询循环与实时出站隔离验证，使用构造隔离样本并明确要求首次查询，未注入正式经验。

复盘对“接近某役”的经验检查时，区分规则条件与策略判断。例如经验“副露后两番役直接速攻”需要核验该役是否食下、是否已保证成役；不能把“有四张宝牌”理解成必然有役。将本次读取的catalog_version与条目ID保存到复盘/记忆证据，后续规则更正时能找出受影响经验。

## 维护与更正

参考表通过源码版本控制维护。稳定ID不随中文名称调整而变化；房间规则以真实配置优先，未支持或未验证的选项标注不确定，不能由参考文字替代合法操作和确定性算点。

自我迭代可以更正/停用自己的策略经验，也可以产生役种表修订建议，附来源、例子和受影响记忆。单次模型总结不能直接改写官方成役条件；表的修订在核对规则和计算用例后按正常Git开发流程更新，不通过经验自动改规则或代码。

本地计算器输出与役种表有矛盾时，先记录并核验来源和房间选项，不能静默更改服务器合法动作，也不能用某次和/放铳结果证明役种定义对错。

## 验收要求

- 参考条目ID唯一、来源和版本可追，门清/副露、食下、役满与规则差异可表示。
- 普通役、役满及变体、宝牌计番、累计役满和流局满贯分类清楚；后三类不能误当成任意手牌的普通成役保证。
- 实时输入检查确认没有全表或大量无关定义，却仍保留相关役种/无役风险的必要事实。
- 复盘可按需找到相关条目，引用的版本和证据进入经验修订；不会把读取规则表等同于某策略已经验证有效。
- 对参考数据的更正有提交/证据，并能检查已引用旧版本的经验；不允许自主记忆工具直接修改参考表。

数据文件交付与加载/检索能力分别跟踪：DOC-003记录本次资料和设计交付，DEV-031实现加载及复盘引用，相关规则/经验/紧凑输入验收增加针对性检查。文档或JSON存在不代表运行流程已接入。
