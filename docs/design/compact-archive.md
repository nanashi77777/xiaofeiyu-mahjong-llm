# 最小持久化牌谱（DEV-033）

用户于2026-10-31要求持久化尽量减少字段，只要能完整还原真实场况。此约定独立于实时模型输入压缩，不改变模型可见信息。

实施顺序：

1. SQLite v2事件行复用已有ID、场ID、小局ID、序号、种类、UTC列；payload仅存事件数据，不再嵌套完整Event。源step及非默认source用独立最小metadata保存。单调时钟不进入历史事件，读回一律标记historical，不能恢复旧操作期限。
2. 场只保留一份最新可恢复快照缓存，省略可由事件重建的public_events及默认值。小局表只保留身份、序号、状态与结果事件引用；大牌表只索引来源事件和该事件内的和牌者位置，不复制结果和手牌。
3. 场况回放只消费实际事件；解释、计划、点击回执、token与经验留在独立records/memories域。历史查询按需展开规范事件，对QQ隐私投影维持原边界。
4. v1到v2迁移先用SQLite backup保存本机备份，再事务迁移；不删事件、未知载荷字段或中断档案。未来版本拒绝写入。
5. 用多小局、赤牌、摸切、鸣牌、立直、多人和与终场构造样本检查全量回放一致；检查迁移、重开、去重、查询及实际本机档案逐事件等价。统计实际JSON字节变化，不用数据库预留页大小冒充内容大小。

保留未知协议字段，避免未来规则或已观察事实被静默丢弃。数据格式版本只在库级记录；不靠缩短名称假装消除语义字段。最新快照是可替换缓存，不能冒充另一份牌谱或模型事实。
