# 模型、结构化小局计划与经验

## 独立实时调用

模型固定 `your-model-id`，base URL 为 `https://model-provider.invalid/v1`。已实测 Responses 路径 `/responses`、`reasoning: {"effort":"none"}`、`store:false`、SSE及严格JSON Schema，真实usage中推理token为0。动态Schema约束请求/动作归属和旧计划版本，本地仍完整验证；输出长度参数的全部组合和取消计费语义不作额外保证，缺失usage继续记unknown。

密钥由本机私密配置注入，示例只留占位。麻将进程直接调用，不经 QQ/DSH 的长会话与工具目录。请求不携带 QQ 聊天、私信或其他活动原文。固定规则前缀保持稳定以利可能的缓存，但不依赖渠道必然缓存。

每次输入包含完整当前可知快照、有序公共行动事实、服务器约束和所有合法动作、当前小局计划、少量相关经验。长整场原始日志不重复塞入；必要历史压成保留事件身份与时序的结构化事实，不能删去影响合法性、振听或防守判断的内容。本家看不到的对手暗手/牌山不可从页面或离线回放混入在线上下文。

已确认采用每次独立的完整决策上下文，不依赖上一响应或聊天历史。具体传输使用[紧凑结构契约](model-wire-format.md)：领域归档保持完整，模型投影移除UI/诊断字段、提取公共字段并按需共享特征。高级紧凑层通过信息等价和真实模型配对检查后才启用，不能用删候选或截断当前小局牌河节省token。

完整[役种参考表](../../reference/yaku/standard-four-player.v1.md)不进入实时请求、system或固定前缀。实时仅提供当前相关的确定事实/条件路线/无役风险；赛后复盘与经验整理按[检索约定](yaku-reference.md)读取相关条目，必要时可看全表。

动作必须通过schema、动作归属和状态版本验证后执行。2026-10-31用户新增的[流式动作契约](streaming-action.md)允许首个完整d对象加字段分隔符提前提交，后续解释/计划异步保存；不凭未闭合的action_id片段点击。非流式兼容模式仍等待完整响应终态。没有强制Schema时使用相同本地校验，不换模型。

## 单次结构化输出

以下为**示例契约**，不是已运行响应；示例状态也不是用户真实牌局。

```json
{
  "schema_version": "decision.v1",
  "q": "k4",
  "action_id": "window-42:discard-7",
  "reason": "点数领先，先保留役牌对子争取快和；本巡先处理孤张。",
  "plan_update": {
    "based_on_plan_version": 2,
    "basis_event_ids": ["event-51"],
    "goal": "领先时争取低风险快和，减少后续失点机会",
    "approach": "fast_win",
    "target_yaku": [
      {
        "yaku": "yakuhai",
        "status": "conditional",
        "basis": ["手中有一组场风对子"],
        "requirements": ["对子成刻，且其余面子能完成"]
      }
    ],
    "priorities": ["优先保留直接进张", "允许有明确役种保障的提速鸣牌"],
    "switch_conditions": [
      {
        "when": "进攻未推进，且对手立直或公开威胁明显上升",
        "then": "重新评估弃和，优先现物防守"
      }
    ],
    "revision_reason": "当前点差适合快和，但手牌尚未形成必须追打的价值"
  }
}
```

- action_id 是唯一可执行选择；reason 是简短、可向用户说明的决策理由，不要求展开内部思维过程。
- 以上展示领域层易读示例；wire格式可使用q绑定的短action_id/事件引用，程序验证后恢复全局身份。字段映射和完整独立输入要求见紧凑结构契约，短ID不免除状态/时间校验。
- plan_update 无变化时为 null；变化时提交一个有长度上限的完整新计划对象。程序分配计划版本并绑定 round_uid/state_version。
- goal 写点数/顺位目的，target_yaku 写牌型方向、依据和必要条件，priorities 写当前打法，switch_conditions 写转守/提速/改路线的条件。
- basis_event_ids 引用实际提供的事件，配合状态版本追溯计划依据；样例中的 event-51 仅为示意。缺失或不存在的引用不能伪装成真实证据。
- 允许“手牌接近混一色”“领先可速攻，未推进且威胁升高时转防守”等具体思路；不接受每步固定复读“提高效率、注意防守”作为有效更新。
- 计划是模型对本小局的策略假设，不是规则断言。役种已成立、点差等事实仍由规则与状态核验；无法支持的计划依据标记为模型错误供复盘，不回写状态。
- 转向条件只供后续模型参考，执行器不能自行根据它选择防守牌。新小局清空；重连恢复同一小局时加载最近有效版本。
- 输出先保存为 proposed；实际动作相符后关联为 adopted。发生人工动作、输入偏差或失效时撤销未采用计划，下一窗口基于实际状态重评。

## 令牌和时延

每请求记录 request_id、用途(decision/repair/review)、模型、input/output/total、cached/reasoning tokens（若返回）、TTFT、完整响应时间、验证与输入时间、取消/错误状态。没有返回 usage 时记 unknown/null，不记为 0，也不猜测为真实计费数。

首版不实施预算限额。短输出、必要信息组织、规则缓存、稳定前缀和并发隔离服务于时间目标；不能通过隐藏合法动作或删除关键场况来节省 token。reason 和计划设合理长度上限并验证实际输出，具体阈值由性能样本调优而非删减必要决策内容。

## 复盘时机和真实性

实时决策只一次模型调用，返回动作/解释/必要计划更新。整场结束或记录中断后异步复盘，不逐手追加第二次调用。复盘任务带事件范围和输入哈希，可恢复、去重；若同场中断后续录，生成新版本，明确旧复盘覆盖范围，不重复计算为独立经验支持。

复盘只对观察到的事件下结论。把“决策当时已知”和“之后揭示/结果”分开，不能用事后对手手牌指责模型当时未知道的事实。区分结果好坏与选择质量，不能凭一次和牌/放铳证明策略正确/错误。

复盘可使用只读read_yaku_reference查成役条件、门清/食下与规则差异，记录catalog_version和条目ID。规则表修订建议与策略经验分开；学习不能直接改表中正式条件，发现错误先核验规则/计算用例并经版本控制更正。

复盘可与后续场并行，但使用独立队列和较低优先级；实时请求不排在复盘后。下一场开始冻结本场可用经验集合，本场复盘新修订在再下一场生效；停用明显错误经验可立即阻止后续召回，但不能重写过去决策的依据。

## 经验和风格

DEV-063为复盘额外提供win_outcomes与本家win_summary，显式区分荣和、放铳和自摸，带来源事件可核查。输入格式版本纳入复盘指纹；已有完成任务不因升级自动批量重审。放铳归属是结果事实，不能单凭一次放铳认定当时选择错误，也不能使用事后揭示的手牌冒充决策时已知信息。

经验与 QQ 人际记忆分库/分域。Memory 含 id、revision、kind、status(candidate/stable/inactive)、适用条件、主张、置信标签、支持/反例事件、来源 match_id、复核记录、替代关系、创建/更新时间和停用原因。

候选经验下一场允许少量带标签召回，不作为必须遵守的规则。策略经验须在后续至少三场不同 match_id 中复核，并完成反例检查，才**考虑**升级；场次数是防过早定论的门槛，不是效果证明。重复重连、同场多次复盘不能凑数。可确定验证的规则错误立即更正；错误经验可立即停用。

模型可提出新增、修订、升级和停用；程序只校验来源、版本、证据去重与权限，不替模型选牌。删除指退出召回，保留修订审计。不能修改核心提示词、计算代码、输入或验证门槛。

风格是有界结构化偏好：例如门清倾向、速度/打点偏好、保位倾向，初始均衡，以最终顺位和避免第四为主要成绩目标。风格不能覆盖合法性、真实场况或强迫在明显不合适时冒险。QQ 的表达风格沿用小肥鱼，不用故意打差或编造大牌塑造人格。

运行时按当前规则、手牌阶段、点差和候选条件检索少量适用经验；保留被召回 ID/revision 以便追溯。召回是信息选择，不是传统策略给动作打分。

当前实现冻结最多50条候选/稳定经验作为本场资格集合，每个窗口按结构化applies_to匹配阶段、本家顺位、门清、对手立直、场类和当前役路线，至多召回4条；同一风格轴只保留一条。模型只收到ID/版本/可信标签/主张/条件/有界偏好及证据数量，完整事件引用留本机。停用或更改主张/条件/风格会阻止旧修订在本场继续召回，新修订下一场冻结生效。风格axis为closed_hand/speed_value/placement_defense，value是-2至2整数，正方向分别是门清、打点、保位防守；基线均衡，不由执行器转换成选牌策略。
