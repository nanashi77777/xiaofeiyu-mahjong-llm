# 自动登录与指令选场开发方案

日期：2026-10-31（Asia/Shanghai）。用户新增的开发计划，取代原先“自动匹配和建房不在范围”的限定。用户继续明确要求选场必须做成QQ小肥鱼可调用的工具；入口包括QQ工具、本机面板、CLI。查询仍用原只读令牌，导航使用独立navigation_token和仅接收规范大厅命令的窄接口，不能调用/control通用控制接口。运行实现按任务注册表跟踪，方案不代表真实入口已经全部验收。

## 指令与流程

| 指令 | 必需参数 | 实际页面操作和结果 |
| --- | --- | --- |
| 登录 | 指定本机账号配置；已有登录态优先 | 打开专用profile，复用有效会话；失效时走真实可见登录页，登录完成后核验大厅或可恢复对局 |
| 段位场 | 场级：铜之间/银之间/金之间/玉之间/王座之间等；四人东/四人南 | 依次选择指定场级与局制，确认实际选项后匹配；无权限/不存在时返回实际原因，不能自动降级或换场 |
| 加入友人房 | 房间码，按字符串保存并保留前导零 | 进入加入房间、输入房间码、提交并核验实际房间；满员/不存在/密码等按页面反馈处理 |
| 创建友人房 | 四人麻将；一局/东风/半庄/人机；本局思考时间 | 按真实UI选择四人及用户选项、设置时间，逐项读回后创建，取得房间码和实际规则；不直接假定客户端的“人机”与对局长度是同一维度 |

时间使用结构化fixed_seconds与bank_seconds，例如5+20、5+10、300+0；也接受客户端支持的预设并转换为同一结构。值域及可用组合从当前页面核验，不能把300秒当300毫秒，也不能自行换成最接近预设。“人机”若在当前客户端是独立入口或独立对手设置，适配器按实际UI映射并明确回显。创建完成先显示房间信息；加入后准备、房主开始等行为由明确指令的范围控制，不因找到房间就自动连续开场。

自然语言先规范为Login/Ranked/JoinFriend/CreateFriend命令，随后用确定流程点击。打牌决策仍全部来自大模型；大厅导航不需每个按钮都请求实时打牌模型。缺少必需参数时请求补充，不猜场级/房间码/时间；控制命令带command_id，重复指令不得重复匹配或建房。

## 登录与可恢复控制

专用持久profile保存登录态；自动登录优先复用会话。需要账号密码时从本机凭据保险库读取，不放源码、牌谱或模型请求。验证码、短信码、扫码和账号二次验证出现时显示等待用户完成的状态，之后可续跑；不把等待登录误报为已登录。没有配置凭据时仅报告需要配置，不为完成计划索取账号密码。

统一状态机：stopped → browser_ready → authenticating → lobby → navigating → matching/room → in_game → completed。异常分failed/cancelled/waiting_user；状态和所选值来自真实页面/只读协议观察。已有活动对局时先接回原局，不用大厅导航覆盖对局。终场保存后默认停止，不自动再开下一场。

导航与打牌共享单一输入租约。切换页面、缩放或重连会使旧定位失效；停止/Esc撤销后续步骤。提交前后分别留简短执行记录；网络超时若结果未知先检查实际状态，避免重复建房/匹配。浏览器窗口与页面身份必须绑定。操作使用可见DOM或画布定位以及浏览器鼠标事件/物理输入，不调用游戏内部动作函数、不发送自造操作包。

## 运行契约与分期

命令kind固定为login/ranked/join_friend/create_friend；command_id由调用方固定，网络重试必须复用。段位tier用bronze/silver/gold/jade/throne，length用east/south，接受明确的中文同义名称；房码必须是保留前导零的ASCII数字字符串。真实Unity客户端核验后，建房要求players=4、length=single/east/south/ai和thinking={fixed_seconds,bank_seconds}；ai按页面并列的人机模式处理，不另猜对手与局制的组合。当前计时预设为3+5、5+10、5+20、60+0、300+0，其他组合明确拒绝，不选相近值。

命令状态与页面阶段分别记录。queued/running/waiting_user/succeeded/failed/cancelled/uncertain表示执行结果；browser_ready/authenticating/lobby/navigating/matching/room/in_game/completed表示进度。journal使用独立本机lobby.sqlite，避免增加牌谱字段。command_id同内容返回原记录，换内容拒绝；不同命令不得并发输入。提交匹配/加入/建房之前先持久化提交标记。停止或进程重启后若结果未核验，标uncertain，续跑先查真实状态，不能再次提交同一动作。

导航与游戏执行器共用非排队输入租约。已经有活动对局、正在打牌或导航时拒绝新导航；停止取消后台任务，物理输入线程完成已发送的按下/抬起后才能释放租约。等待人工验证时不占用鼠标；续跑仍重新检查页面、停止状态和活动对局。仅浏览器会话认证成功不能证明已完成选场；真实房规/场级/时间仍由后续页面适配和独立VAL-013验证。

QQ新增mahjong_navigate与mahjong_navigation工具：前者接收明确规范命令，后者只查询/取消/续跑已存在的命令。用当前QQ消息ID形成稳定command_id，不能把角色想象或历史/引用内容当成一次新选场请求。沿用当前会话key与白名单，不改触发概率，不由QQ输出选择弃牌。未完成的页面适配必须返回navigation_adapter_not_ready；不能把“命令已受理”回复成“已进入牌局”。

## DEV-073：退出房间的实际结果

真实创建单局3＋5房后，返回按钮直接收到leaveRoom成功并回到大厅；旧控制入口固定报告dialog_opened，验收工具随后点击不存在的确认页失败。退出动作应在按下前记录意图，优先核验本次新leaveRoom回执；只有实际识别已校准确认页才报告dialog_opened。无回执且无可确认页面保留uncertain，同ID不重按。测试工具以实际结果决定是否第二次确认。保留原矩阵失败，不重写为成功。
